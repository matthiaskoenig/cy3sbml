# SBML layout support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read the layouts of the SBML `layout` package into one glyph subnetwork per layout, whose view shows the nodes at the positions and in the sizes of the glyphs (#71).

**Architecture:** `LayoutReader` collects the layouts of a model in the `ConversionContext`. After `SubnetworkBuilder`, the new `LayoutNetworkBuilder` creates one subnetwork `<name>__layout_<id>` per layout in the root network of the model: a node per glyph (a copy of the node it represents), edges from the species reference glyphs or generated from the model edges, and the geometry in local columns. `SBMLReaderTask.buildCyNetworkView` places the nodes from the columns and uses a layout style that `StyleManager` derives in code from every cy3sbml style.

**Tech Stack:** Java 17, JSBML layout extension (pinned fork), Cytoscape 3.10 API, JUnit 6, Mockito, Cytoscape test support (`NetworkTestSupport`, `NetworkViewTestSupport`).

**Spec:** `superpowers/specs/2026-09-29-layout-design.md`

## Global Constraints

- Layout package version 1. Read only: no export of positions into SBML.
- Not covered: curves (bends), render package, free-standing text glyphs, z dimension.
- One layout never fails the import: failures of one layout network are logged as warnings and that network is left out.
- The base network of the main model stays the first network of `getNetworks()`.
- No new warnings in `./mvnw -B -q verify`; Spotless (`./mvnw -q spotless:apply`) and the `lint` profile (`JAVA_HOME=~/.local/share/jdk-25 ./mvnw -B -Plint clean verify`) pass.
- Never use the em dash character; no agent attribution in commits, PRs, code or docs.
- Do not hand-edit `docs/release-notes.md`, `site/` or `CHANGELOG.md`.
- Use the `SBML` constants, not string literals, for column names and types.

## Review Focus

1. A model with a layout that references ids that do not exist (typo, element deleted): glyph becomes its own node, no exception. Test in Task 3.
2. A glyph without bounding box, or with position but no dimensions: defaults, no NPE (JSBML getters return null or NaN). Test in Task 2.
3. A species reference glyph whose species glyph id does not exist, or a reaction glyph without reaction: skipped / own node, no exception. Test in Task 4.
4. The comp flat model and model definitions with layouts: a layout network per model source, names prefixed like the networks of the collection. Test in Task 5.
5. Two layouts with the same glyph ids in one model: the networks are independent (glyph lookups per layout). Test in Task 3.

```java
record GlyphBox(double x, double y, double width, double height) {
    static final double DEFAULT_SIZE = 30.0;

    static GlyphBox of(GraphicalObject glyph) {
        double left = 0, top = 0, width = DEFAULT_SIZE, height = DEFAULT_SIZE;
        if (glyph.isSetBoundingBox()) {
            BoundingBox box = glyph.getBoundingBox();
            if (box.isSetPosition()) {
                left = valueOr(box.getPosition().getX(), 0);
                top = valueOr(box.getPosition().getY(), 0);
            }
            if (box.isSetDimensions()) {
                width = valueOr(box.getDimensions().getWidth(), DEFAULT_SIZE);
                height = valueOr(box.getDimensions().getHeight(), DEFAULT_SIZE);
            }
        }
        return new GlyphBox(left + width / 2, top + height / 2, width, height);
    }
    static GlyphBox centroid(Collection<GlyphBox> boxes, double size) { ... mean of x, y ... }
    private static double valueOr(double value, double fallback) {
        return Double.isNaN(value) ? fallback : value;
    }
}
```
